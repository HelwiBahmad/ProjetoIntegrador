O QUE É O PROJETO?
================================================================================

Comunidade em Sinais é uma plataforma web para a comunidade surda brasileira,
oferecendo:

✅ Portal de notícias com CRUD completo
✅ Informações sobre direitos e legislação
✅ Calendário de eventos
✅ Espaço para histórias pessoais
✅ Autenticação segura (3 perfis: leitor, autor, admin)
✅ Interface moderna com Bootstrap 5
✅ Painel administrativo completo
✅ Arquitetura profissional (MVC + SOLID)

================================================================================
TECNOLOGIAS UTILIZADAS
================================================================================

FRONTEND:
- HTML5, CSS3, JavaScript (ES6+)
- Bootstrap 5.3.0 (responsivo e acessível)

PADRÕES DE DESIGN:

- Repository Pattern
- Service Layer
- Factory Pattern
- Middleware Pattern

================================================================================
AUTENTICAÇÃO
================================================================================

Sistema de 3 perfis:

1. LEITOR
   - Visualizar notícias, direitos, eventos, histórias
   - Sem permissão de criação/edição

2. AUTOR
   - Todas as permissões do leitor
   - Criar e editar próprias notícias e histórias
   - Não pode deletar

3. ADMIN
   - Acesso completo
   - Gerenciar todos os conteúdos
   - Gerenciar usuários e permissões
   - Painel administrativo

Segurança:
- Senhas criptografadas com bcryptjs
- Tokens JWT para autenticação
- Middleware de autorização em cada rota

================================================================================

NOTÍCIAS:
GET    /api/noticias              → Listar

POST   /api/noticias              → Criar (autor/admin)
PUT    /api/noticias/:id          → Editar (autor/admin)

DIREITOS:
GET    /api/direitos              → Listar
GET    /api/direitos/:id          → Detalhes
POST   /api/direitos              → Criar (admin)
PUT    /api/direitos/:id          → Editar (admin)
DELETE /api/direitos/:id          → Deletar (admin)

EVENTOS:
GET    /api/eventos               → Listar
POST   /api/eventos               → Criar (admin)
PUT    /api/eventos/:id           → Editar (admin)
DELETE /api/eventos/:id           → Deletar (admin)

HISTÓRIAS:
GET    /api/historias             → Listar
GET    /api/historias/:id         → Detalhes
POST   /api/historias             → Criar (autor/admin)
PUT    /api/historias/:id         → Editar (autor/admin)

AUTENTICAÇÃO:

ARQUITETURA E PADRÕES
================================================================================

PADRÕES DE DESIGN IMPLEMENTADOS:

1. MVC (Model-View-Controller)
   - Models: Estrutura de dados no banco
   - Views: Arquivos HTML e JavaScript
   - Controllers: Camada HTTP (rotas)

2. Repository Pattern
   - Abstração de acesso aos dados
   - Facilita testes e manutenção
   - 5 repositórios criados

3. Service Layer
   - Lógica de negócio centralizada
   - Reutilizável entre controllers
   - 5 serviços criados

4. Factory Pattern
   - ApiResponse.js: Padroniza respostas JSON
   - Consistência em toda API

5. Middleware Pattern
   - Autenticação
   - Autorização
   - Tratamento de erros
   - CORS

PRINCÍPIOS SOLID:

S - Single Responsibility
  Cada classe tem uma única responsabilidade bem definida

O - Open/Closed
  Aberto para extensão, fechado para modificação

D - Dependency Inversion
  Controllers dependem de Services, não de implementações diretas

I - Interface Segregation
  Métodos específicos, sem métodos genéricos excesivos

L - Liskov Substitution
  Controladores podem ser substituídos sem quebrar a aplicação
